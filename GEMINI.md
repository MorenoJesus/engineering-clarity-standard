# Engineering Clarity — Gemini CLI Instructions

Apply Engineering Clarity Standard (ECS) to technical prose: requirements, user stories, acceptance criteria, pull request descriptions, API docs, ADRs, runbooks, plans, and explanations. Use one precise term per concept, name actors and conditions, state observable results, and preserve exact identifiers, units, API contracts, and security constraints.

Do not invent requirements, test results, validation evidence, or recovery guarantees. State assumptions and unknowns explicitly. For drafting or reviewing technical artifacts, load the `engineering-clarity` Agent Skill from `.agents/skills/engineering-clarity/` where skills are enabled.

ECS is STE-inspired writing guidance, not formal ASD-STE100 compliance. Respect stronger repository- and organization-specific rules.
