# Engineering Clarity — Claude Code Instructions

Use Engineering Clarity Standard (ECS) for technical prose. Apply precise terminology, direct language, explicit conditions, measurable acceptance criteria, and honest verification statements. Never invent test results or silently change requirements. Preserve exact technical identifiers and architectural meaning.

Use the `engineering-clarity` skill in `.claude/skills/engineering-clarity/` when creating or reviewing user stories, PR descriptions, technical docs, ADRs, runbooks, or similar writing. If it does not load automatically, invoke `/engineering-clarity` or read its `SKILL.md` directly.

This is STE-inspired software documentation, **not** formal ASD-STE100 compliance. Follow the project-specific rules already established in this repository.
